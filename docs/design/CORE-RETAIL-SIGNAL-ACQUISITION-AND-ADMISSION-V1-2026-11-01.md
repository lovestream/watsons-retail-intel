# 经营情报采集与筛选：一次性全链路修复候选（2026-11-01）

## 0. 裁定、目标和授权边界

目标：**中国大陆屈臣氏、直接美妆个护竞对、即时零售商家经营机制，以及美妆个护品牌/渠道/合规的具体新增经营动作**。信息库不是泛新闻数据库、证券快讯聚合或餐饮招商摘要。可用事实少时允许周报只有1～3条，而不是为了凑数填充。

此文对应独立候选分支 `fix/retail-intel-scope-end-to-end-20261101`，以PR #6候选为基点，**不自动合并、部署、调整Cron、修改NAS已有事件账本、追补10/12～18或发送邮件**。新代码在仓库但尚未执行NAS的25/162/旧周报真实素材验收。Stage 0基线及之前已冻结证据不得原地重写。

## 1. 根因：为什么一轮轮补关键词无效

1. 原文章过滤按「核心关键词+规则分数+新发现时效」直通main，如`newly_discovered + core_hit + score≥4`、`day_primary + score≥6`。关键词“美妆”“屈臣氏”在餐饮、招聘、股市文章**正文背景**也会出现，不能证明主事件相关。
2. 广义词库混合即时零售、美妆、泛便利店/商超、生活服务（“大众点评、到店、山姆、便利蜂”等）；单词命中既不能说明主营对象，也不能说明有新经营动作。
3. 启用的发现源仍搜“即时零售 最新”“三国杀”等宽泛话题，加之RSSHub/快讯，泛行业新闻占用采集上限；且现有代码先按数据来源组依次采集、按到达顺序截取前600条，未先按目标业务优先级排。
4. P01回退/规则模式存在LLM不可用、低证据新闻仍被源优先级加权放行；文章过关后，P02拆出的不相关子事件可能另入events_raw。月年报从旧events_analyzed提取，历史股市与餐饮事件也可能“复活”。
5. 已有`event_novelty_check`聚类和事实hash会去掉所有数字：价格、SKU、店数变动可能被合并成同事实。此机制涉及现有账本兼容性；**本轮没有冒险修改旧账本/hash版本**，仅将安全的跨日**文章同源同内容**去重前移，并把事件hash数字变动列为后续独立兼容迁移验证点。
6. 发表日与发生日不能相互代替。用户已明确允许真实来源日期写成“据36氪2026年10月30日报道”，而不是编造发生日。

## 2. 新的统一准入契约

**入库主池必须全满足**：
1. 主题与中国大陆屈臣氏/直接竞对/即时零售商家机制/个护美妆经营相关；
2. 标题与导语指向可描述的**主体+动作**（如开店、入驻、配送、佣金、新品、平台商家规则、真实合作、合规政策实施），不能只在正文“提到美妆”；
3. 文章有来源链接，事件的动作须有来源标题/摘要/原文支持；时间不明确可用 **reported/published口径**，不能伪填occurred；
4. 不是重复同一媒体同一事件，若新价格/店数/执行状态或新独立来源则保留候选；
5. 明确属于资本市场行情、招聘、冰淇淋/餐饮、健身、泛ERP/研报的**主话题**始终拒绝，主体背景词及LLM高分不能豁免。

三态：`ACCEPT` 可进入规则后续时间、网页、真实性门；`REVIEW` 只做待核线索，禁止进正式事件/报告；`REJECT` 丢出业务情报池，但日志保留审计理由。绝不把暂未发生的计划写成已实施。

允许：屈臣氏经营创新/门店/会员/O2O；丝芙兰/万宁真正门店和渠道变化；美团闪购/京东秒送/淘宝闪购商家规则、履约与美妆合作；美妆个护品牌入驻/新品渠道/合规重大变化。泛生鲜仓扩张、商超县域扩张、纯股价/财报、外卖餐饮动向均非自动主池。**人工单条例外**：用户此前明确指定“山姆、奥乐齐、盒马掘金县级市场”，仅`零售圈+2026-10-28+该标题`保留为可审计的单件编辑批准，绝不扩展成商超新闻默认准入。若最新品类口径要删除历史人工例外，需要另行撤销该项，不可静默变成广义白名单。

## 4. 正反例的一次性验收合同

**正例，必须逐条审阅原始来源并保留**：
- 屈臣氏“共创”具体经营创新，2026-10-30媒体报道；
- 屈臣氏门店、会员、即时零售合作等真实动作；
- 丝芙兰、万宁等直接竞对的真实布局；
- 美团闪购/京东秒送/淘宝闪购与个护美妆或跨品类商家经营机制有关的变化；
- 化妆品品牌入驻、零售新品、合规政策及有经营影响的行动；
- 已人工批准的零售圈2026-10-28县域商超案例**仅一条例外**。

**负例，必须0误放**：野人先生冰淇淋、寿司郎被罚、上美股份高薪招聘CHO、SAP市场报告、股市162条（以NAS冻结样本为准）、泛餐饮/健身/生鲜、单纯市场规模分析、证券/研报、仅正文背景带“屈臣氏”的无关事件。

**不可只看过滤结果数量**：25条保留素材必须逐条与真实原标题、摘要、原文、动作状态核对。没有原文的记录只能证明“据媒体报道”，不得擅自说已证实动作。源业务主张若抽取丢失，要列`false_negative`，不能靠删除更多新闻提高准确率。

**跨日/变更验收**：同源同标题同事实不再新增；新店数20→30、平台规则已宣布→已实施、实质变更不被重复判定；不同独立原始来源保留可追溯关系；历史旧库仍不得进周月年正式事实包。

## 6. 已知独立风险（不隐瞒）

- 全量RSSHub快讯与搜索覆盖仍可能受来源发布时间、feed容量和API限额影响；本候选不更改生产定时任务，必须监控**高价值信号召回率**而非原始抓取条数。
- 现有`event_novelty_check`剔除数值的旧fact_hash算法，可能对真实数字更新误判；修改hash需明确版本与旧账本兼容，不能趁此覆盖生产账本。本候选的跨日**文章**去重不等于事件聚簇彻底升级。
- P02长正文4200字token成本仍未在受控LLM环境测量；本轮不运行任何收费模型。
- 尚未接入真实新素材、未做人工标注、未运行NAS回归或真实端到端LLM生成；代码提交与测试源文件存在均**不等于测试通过**。
- 报道口径是媒体发文日期，而不是发生日期，P09仍应验证主体、动作与状态；没有可信发表日则写“近期媒体报道”，禁止凭抓取日期编造。
