## 二、由此得出的两个硬指标

### ① 准入精确率 = 100%

### ② 重复识别是唯一矛盾

## 三、去重口径对比（关键结论）

| 口径 | 结果 | 是否正确 |
|---|---|---|
| 按 URL 去重 | **5** | ❌ 错误 |
| 按身份（主体\|动作）| **7** | ✅ 正确 |
| 人工 keep | 8（含 1 条重复）| 参考 |

### URL 为什么不能做去重键

`36kr.com/p/4045150101247623` 一篇报道同时讲山姆/盒马/奥乐齐三个零售商的县域动作。
**你的标注也把这三条都 keep 了**——证明它们确实是 3 个独立事件。
按 URL 去重会错并为 1 条，丢失 2 个事件。

### 身份归并 7 条 vs 人工 8 条的差异（1 条）

唯一差异在「菜鸟」：

| 日期 | 抽取方式 | URL |
|---|---|---|
| 2026-10-01 | **规则兜底** | `cls.cn/detail/2176860` |
| 2026-10-20 | LLM 抽取 | `cls.cn/detail/2176860` |

**两条 URL 完全相同，是同一篇文章**。10-01 那条是 `[规则兜底]` 标记，
说明当天 LLM 抽取失败、降级用规则生成。

→ **身份归并的 7 条是正确结果**；人工的第 8 条是抽取质量产物。

## 四、由此发现的数据质量缺陷（已修复）

**规则兜底抽取会与 LLM 抽取并存**，被当成两条不同事件：

- 37 条准入中，规则兜底占 **11 条**
- 其中 **10 条被判重复**，1 条被人工 keep（即上面那条）

### 修复

新增 `extraction_quality()` + `is_lower_quality_dup()`：
同 URL 同身份时，**规则兜底版本让位于 LLM 版本**。

```python
if prev_q == "llm" and cur_q == "rule_fallback":
    return True   # 判为 observation_only，不生成新事件
```

新增 3 项测试：
- 同 URL：先 LLM 后规则兜底 → 丢弃兜底
- 同 URL：先规则兜底后 LLM → 接受 LLM 版本
- `extraction_quality` 正确识别 `[规则兜底]` 标记
