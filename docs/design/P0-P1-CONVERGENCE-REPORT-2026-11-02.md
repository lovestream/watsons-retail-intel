## P0-1 事件身份与真实更新识别（已完成）

### 从 2 维扩展到 5 维 + 内容优先比较

**v2 关键改变：先比内容，再判同源**（原逻辑同 URL 即判重复，会漏掉内容更新）。

判定顺序：
```
内容完全一致? -> observation_only
对象/渠道/地点互斥? -> distinct（另一件事）
量化事实变化 or 阶段推进? -> material_delta
文本不同但无实质变化 -> observation_only（改写/转载）
```

**五维度**：主体 / 动作 / 对象 / 渠道 / 地点
- 身份键 = `主体|动作`（对象/渠道/地点作为 compare() 的约束，不放进键）
- 原因：同一动作的重复报道常详略不一，对象入键会把同一事件拆成多条（实测「菜鸟」被拆成 2 条）

### 迭代中修掉的 3 个真实缺陷

| # | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| 1 | 动作族按关键词优先，导致「菜鸟加入…提供配送」被拆为两个事件 | E 层出现 2 条菜鸟事件 | 引入 `ACTION_PRIORITY`：业务主动作优先于修饰动作 |
| 2 | 数字变化判定早于对象互斥，导致「美妆增长100% vs 3C增长200%」被判为同一事件的更新 | 测试失败 | 对象/渠道互斥判定前置 |
| 3 | 地点入身份键，导致「山姆上海开店」与「山姆成都开店」合并 | 测试失败 | 地点移出键，改为 distinct 判据（"全国"/"县域"作包含关系不判互斥）|
