## 一、S3 实施（隔离 worktree）

### S3-1 采集优先级修正

**问题确认**：`collect_daily_articles.py:2146` 原顺序为
`["xcrawl","tavily","rsshub","rss","web","baidu_news"]`，
泛搜索（xcrawl/tavily）排在垂直订阅（rsshub/rss）之前，且接到 800 条即 break。
泛搜索产量冲高时会把高质量垂直订阅挤掉。

**确定性测试**（`tests/test_collection_priority.py`，5 项）：
- 现状顺序确实把泛搜索放在垂直订阅前 ✅
- 泛搜索产量 700 时，rsshub 被截断 ✅
- 改为垂直优先后，rsshub 完整保留、tavily 被截断 ✅
- 上限严格生效 ✅
- 零产量方法不阻塞 ✅

**修改**：
```python
_default_order = ["rss", "rsshub", "web", "tavily", "xcrawl", "baidu_news"]
_method_order = list((collection_limits.get("method_order") or _default_order))
```
可用 `config/sources.yaml` 的 `collection_limits.method_order` 覆盖，便于回滚。

### S3-2 事件身份合同（新增 `skills/event_identity.py`）

区分「同稿重复发现」与「新增业务事实」：

| 判定 | 触发条件 | 结果 |
|---|---|---|
| `new` | 首次出现该身份 | 生成事件 |
| `observation_only` | 同 URL 或同内容指纹 | **只增加观测，不生成事件** |
| `material_delta` | 门店数/单量/城市数/价格变化，或阶段推进 | 生成实质更新事件 |

身份键 = `主体 + 动作族 + 阶段`，不含数字（数字用于判定 delta）。

**阶段判定修正**（测试发现并修复）：
原文「宣布将上线X」同时含"宣布"与"上线"，原逻辑取最后命中会误判为 launched。
现规则：出现未来时态（将/拟/计划/预计/即将/有望/筹备）→ `announced`。

**测试**：`tests/test_event_identity.py` **7/7 通过**，覆盖
菜鸟同稿 23 次、跨源转载、门店数 20→30、宣布→上线、价格变化、措辞差异。
