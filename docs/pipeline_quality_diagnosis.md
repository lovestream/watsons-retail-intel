## 按环节逐层诊断

### 1️⃣ 采集层 (collect_daily_articles) — ⚠️ 严重不足

**现状**：
- 34篇清洗后文章，其中 33 篇来自 tavily_gap_search，仅 1 篇来自 RSSHub
- 99个原始事件中，94个 confidence=low（95%）
- 来源分布极度单一：98/99 事件来自 tavily_gap_search

**问题**：
- RSSHub 源几乎全部失败（34个配置源只产出1篇），说明 RSS 采集逻辑有问题
- Tavily gap search 补了 33 篇，但搜索关键词未覆盖核心场景（监管政策、竞对动态、市场数据）
- 缺少一手数据源：虎嗅、36氪深度文章、平台官方公告、行业研报等

**参考日报的信息量来源**：35.97亿罚单、抖省省796万日活、7家平台罚金明细——这些全是有深度事实的重大新闻，而我们的采集中只有"美妆个护促销满减"这种表面信息

**改进方向**：
1. RSSHub 源排查修复，确保 34 个源可靠产出
2. Tavily 搜索关键词升级：增加"监管/政策/罚单/合规"、"行业数据/GMV/市场份额"、"竞对动作/名创优品/调色师"
3. 增加一手数据源：政府监管信息、上市公司财报、行业报告

---

### 2️⃣ 过滤层 (filter_relevant_articles) — ⚠️ 过松

**现状**：
- 34篇 → 34篇全部保留（0篇被规则过滤淘汰）
- 89篇被 LLM 语义过滤拒绝

**问题**：
- 规则过滤器没有起任何作用——34篇全过
- 留下的34篇多数是低质量的促销信息（满59减10之类），而非深度行业分析

**改进方向**：
1. 规则过滤需要增加"信息密度检测"——满减/优惠券类促销信息不应作为核心情报源
2. 增加"事实深度打分"维度——只报了一个价格的活动 vs 分析了行业趋势的深度文章，权重应天差地别

---

### 3️⃣ 事件抽取层 (extract_events) — ⚠️ 粒度过细

**现状**：
- 34篇文章 → 99个事件 → 94个 confidence=low
- 平均每篇文章抽 2.9 个事件——切得太碎

**问题**：
- 一篇文章的核心论点被拆成多个碎片事件
- 例：一篇关于"即时零售之下第一批美妆受益者"的综合分析文章，只抽出一个碎片事件"屈臣氏在淘宝闪购美妆个护行业订单量和成交额双第一"，丢失了全文的深度分析和上下文

**参考日报的做法**：
- 将"35.97亿罚单"这个重大事件展开为完整叙事：事实→解释→判断→对屈臣氏的意义
- 每个动态是一段完整的行业洞察，而非一句碎片事实

**改进方向**：
1. LLM 抽取 prompt 从"每篇文章抽取N个事件"改为"提炼每篇文章的核心洞察，合并相关事实为一个完整事件"
2. 增加"事件聚合"步骤——同一篇文章或同一主题的多个碎片事件应合并
3. 增加"信息深度评级"——区分"促销通知"和"政策深度分析"

---

### 4️⃣ 评分层 (score_events) — ⚠️ 无法区分质量

**现状**：
- 99个事件 → 全部 P2（47个）或 ARCHIVE（52个），0个 P1
- 最高加权分 4.1 / 最低 1.4，区分度极低

**问题**：
- 缺乏"信息深度"维度——"美妆个护悦护周满59减10" 和 "屈臣氏订单量双第一" 的得分差距不够大
- source_credibility 维度全部给低分，导致所有事件都低置信
- 没有考虑"趋势聚合效应"

**改进方向**：
1. 增加"信息深度"评分维度：促销通知=1、行业动态=3、政策/监管=5
2. 修正 source_credibility：区分"转载/聚合"和"原创报道"
3. 增加"趋势聚合加分"：同一方向的多个事件合并后应获得额外权重

---

### 5️⃣ 影响分析层 (analyze_business_impact) — ⚠️ 分析太浅

**现状**：
- 每个事件生成一个模板化的 business_analysis dict
- Top 事件的 recommended_action = "立即复盘淘宝闪购成功因素...复制到其他平台" —— 跟模板差不多

**参考日报的做法**：
- 每个动态4层：事实(具体数据) → 解释(因果逻辑) → 判断(趋势预测) → 意义(具体动作)
- "对屈臣氏的意义"不是泛泛的"应该关注"，而是具体到"线下3000+门店的《化妆品经营备案凭证》数字化"、"200万专项预算采购区块链存证服务"
- 市场份额预测有具体数字：美团42% / 京东30% / 抖音15% / 淘宝10%

**改进方向**：
1. LLM 分析 prompt 要求"具体数字、具体预算、具体时间节点、具体负责人"
2. 增加"行业格局预判"维度——对市场份额、时间线给出量化预测
3. 增加"竞对监控方案"维度——指明盯谁、盯什么指标、什么频率
4. 增加"行动层级"：立即可做 / 建议试点 / 需要总部支持 / 持续观察

---

### 6️⃣ 日报生成层 (generate_daily_report) — ⚠️ 模板化

**现状**：
- V1 规则模板是每个事件一行行机械拼接，没有深层叙事
- V2 prompt 被"low confidence 不能写确定性结论"约束得太死——95%事件是 low confidence → 整个日报变成"待验证线索汇总"
- "唯一建议动作"如果是"不建议贸然"，说明 LLM 在所有信号都不确定时选择躺平

**参考日报的做法**：
- 每个动态是完整的故事线，不是碎片枚举
- "对屈臣氏的意义"是整个日报最有价值的段落——具体的、可执行的建议
- 行动建议分4类4层，每条都有预算/规模/时间线

**改进方向**：
1. **V1 模板改造**：从"事件清单"改为"洞察叙事"——每个核心信号写成 事实→解释→判断→意义 四段式
2. **V2 prompt 改造**：取消"low confidence 事件只能作为待验证线索"的硬约束，改为"事实部分标注⚠️，但经营判断仍需明确"
3. 增加"行业格局"章节：要求 LLM 推演市场份额变化、趋势判断
4. 行动建议模板改造：分4层，每层要求具体数字

---

### 7️⃣ 审稿层 (editor_review) — ⚠️ 只检查合规，不提升质量

**现状**：
- 审稿只做"合规检查"（字数、章节、警告标记），不做"质量检查"
- 不检测"内容是否有深度"、"行动是否具体"、"是否有量化洞察"
- "唯一建议动作"是"不建议贸然推动"通常应打回

**改进方向**：
1. 增加"质量门控"：唯一建议动作不能是空话
2. 增加"信息深度检查"：核心信号段必须包含至少1个量化数据点
3. 增加"行动具体性检查"：每个建议必须包含至少1个可量化指标

---

## 核心结论

**最关键的瓶颈是前三层：采集→过滤→抽取。**

垃圾进，垃圾出。如果采集到的都是"美妆个护悦护周满59减10"这种信息，再怎么优化分析和生成，日报也不可能产出"35.97亿罚单推动行业洗牌"这种深度洞察。

但后三层也有明显的模板化和浅层化问题。优化顺序：

1. **P0 采集层**：修复 RSS 源 + 升级 Tavily 搜索关键词 → 确保每天5-10篇高质量深度文章
2. **P1 抽取层**：从"碎片事件"改为"洞察聚合" → 合并同一主题的碎片事实
3. **P2 分析层**：从"模板化泛谈"改为"四段式深度分析" → 事实→解释→判断→意义
4. **P3 生成层**：从"事件清单"改为"洞察叙事" → 核心信号写成完整故事线
5. **P4 审稿层**：从"合规检查"升级为"质量门控" → 检测深度、具体性、可执行性
