# PROJECT_RULES — Muse 独立版业务硬规则

> 提炼自原仓库 `README.md`、`project.yaml`、`docs/01–08`、`docs/acceptance_criteria.md`、`config/*.yaml` 与 `muse/MASTER_GOAL.md`。
> 本文件是 Muse 独立版每次运行必须遵守的规则。业务边界变更必须在本文件留版本记录，并同步 CHANGELOG。
> 版本：v1.0（2026-10-24 建立）+ R1 补丁（2026-10-24，见 §9）

## 1. 服务对象与产品定位

- 服务对象：负责屈臣氏中国大陆线上零售多渠道经营的使用者。
- 产品不是新闻聚合，而是经营情报：发现 → 核实 → 去噪 → 事件化 → 历史去重 → 经营分析 → 周期报告 → 复盘改进。
- 只采集公开信息；不接触品牌自有销售数据；不产生经营结论以外的自动动作。
- 核心理念：少而精。没有足够有效事件时，明确写「本期有效新信号不足」，不得硬凑。

## 2. 业务边界（硬规则，不可突破）

### 2.1 渠道三层（固定）
1. **即时零售（主监测）**：美团闪购、京东秒送/京东到家、淘宝闪购（饿了么）、抖音小时达。
2. **B2C 旗舰电商**：天猫官方旗舰店、京东旗舰店——仅在有证据显示跨渠道影响时延伸。
3. **ToB/经销**：天猫超市、京东自营、经销商体系——同上。

### 2.2 品类
个护美妆：护肤、彩妆、防晒、面膜、洗护发、口腔护理、身体护理、香水香氛、男士理容、经期/私护、功效成分（烟酰胺、视黄醇、水杨酸等）及相关场景消费。

### 2.3 地域
仅中国大陆。香港、澳门、台湾及其他境外主体默认排除；仅当事件主体是在中国大陆的实际经营动作、且有明确证据时，才可严审后纳入，并在报告中注明。

### 2.4 硬排除（命中即不进正式池）
- 资本市场内容：股价、涨停、评级、目标价、盈利预测、IPO、投研观点；
- 无即时零售/个护美妆经营交集的泛新闻、泛电商资讯；
- 纯境外主体新闻；无证据传闻；重复转载；老事件伪装新动态；
- 低价值广告、单一泛关键词碰瓷新闻、软文式品牌通稿（无具体经营事实者）。

## 3. 事实与证据规则（硬规则）

- 每个进入正式池的事件必须有：可点击的原始来源 URL、明确发表时间、明确事件发生时间。
- 数字断言（增长、市占、GMV、订单量、门店数等）必须能在来源证据中找到原文与统计口径；无证据不写，写则注明来源。
- 无法核实的数值或主体标注「未核实」，不得用推测补齐。
- 多家媒体报道 ≠ 事实成立：核查来源是否独立、是否互相转载、是否为单方广告主张。
- 事实、机制推断、建议动作三者必须分开书写；建议是探索性行动，不得伪装成企业已执行。
- 需要屈臣氏内部数据（销售、毛利、库存、流量）才能验证的，列为「内部验证依赖」，不编造。
- 无法访问的页面标记「无法核验」，不编造正文，不绕过验证码/登录限制。

## 4. 事件化与去重（硬规则）

- 一篇文章 ≠ 一个事件。同一平台政策被多家媒体报道，合并为一个事件，多源作为 supporting_urls。
- 同一事件出现真实新进展时，记为原事件的 update（update_of），不得误杀，也不得当作全新事件重复计数。
- 去重判据：主体 + 动作 + 关键实体重合，或标题归一化相似度高（参考原系统 Jaccard 0.65 / 实体重合 0.6）。
- 报告按**事件发生日**归入周期，不按发现日。

## 5. 分级（继承原 scoring.yaml 八维，简化执行）

八维参考权重：屈臣氏相关度 0.24、战略重要性 0.18、可执行性 0.14、影响范围 0.12、来源可信度 0.12、数据丰富度 0.10、时效性 0.06、新颖性 0.04（0–5 分制）。

- **P0**（≥4.3）：直接影响屈臣氏经营的平台规则/政策、重大竞对动作、监管变化，须即时提示。
- **P1**（3.6–4.3）：明确经营相关、值得纳入周报的信号。
- **P2**（2.8–3.6）：归档备查、背景跟踪。
- **ARCHIVE**（<2.8 或硬降级）：不进报告。

硬降级（继承原配置）：无 source_url → ARCHIVE；fact 为空 → ARCHIVE；来源可信度低（聚合转载/未知来源，tier≤2 且无独立佐证）→ 最高 P2；证据文本为空 → 最高 P2；event_type 为背景/不明确 → 最高 P2。

## 6. 来源可信度分层（继承原 source_tier_map）

- **Tier 5（可信度 5）**：平台/品牌官方、公司公告、监管机构（药监局 NMPA 等）。
- **Tier 4（4）**：晚点 LatePost、36氪、财新、华尔街见闻、界面、虎嗅。
- **Tier 3（3）**：行业垂类——亿邦动力、联商网、品观、聚美丽、CBNData、青眼、化妆品观察等。
- **Tier 2（2）**：搜狐、新浪、今日头条、百家号、微信公众号文章等聚合/转载。
- **Tier 1（1）**：未知来源（默认不单独支撑 P0/P1）。

## 7. 报告规则（硬规则）

- 不恢复每日推送日报。正式产物：**周报（6 章）、月报（7 章）、年报（8 章）**；可按需做专题。每日只做追踪入池。
- 覆盖率门槛（normal）：周 ≥0.85、月 ≥0.90、年 ≥0.95（以有效采集天数计）；未达 normal 必须在报告显著披露覆盖不足，不得宣称覆盖正常。
- 报告内不得出现内部 event_id、调试标签、模型思考内容、空占位。
- 每期优先呈现 3–5 个重要经营判断，每个判断配可点击证据 + 明确动作（渠道 + 动作 + 验证时间窗 + KPI + 反例/不确定性）。
- 每期结尾留「下周期待验证的假设与指标」，下期回看。
- 简体中文；北京时间（Asia/Shanghai）；报告显著标注完整覆盖区间。
- 未通过事实审校的产出只能标注为「不可发布草稿」。

## 9. R1 硬规则补丁（2026-10-24，PR #1 审查后新增）

- **转载时间 ≠ 事件日期**：每条事件必须同时标注 event_date、published_date、first_seen；三者不一致时以最早首发为准；转载日与事件日差 >30 天时自动标旧闻嫌疑，不得以转载日冒充新动态。
- **P1 必须有即时零售交集**：纯 B2C 旗舰数据即使数字正确，也只能记观察 / 背景，除非补出可核实的即时零售承接证据（平台战报、同款 SKU 即时零售销量或价差、入驻 / 闪电仓动作）。
- **政策三段拆分**：落款日 / 公开发布日 / 施行日分开写；“制定 / 支持 / 探索”不得写成已普遍落地或已直接降低成本；媒体转载不得记 source_type=official。
- **禁止全称否定**：只能写“在本次已覆盖的来源和检索窗口内未发现经核实的新发布”，并附检索覆盖与盲区。
- **核验分级**：L1 原始报道已读取 / L2 官方信息已核实 / L3 独立多源已核实；P1 必须有首发或官方链接，转载不冒充第一手。
- **最小可审核 manifest**：每次运行附查询词 / 检索时刻 / 命中数 / 候选 ID / 排除理由 / 失败来源；“原始候选”与“初搜命中”不得混用同一计数口径。

## 8. 权限与安全边界（硬规则）

- 仓库为公开仓库：`muse/` 只写可公开的规则、脱敏案例与经审校成果；禁止写入 API Key、Cookie、凭证、私人信息、未授权内部经营信息。
- 不修改原 QwenPaw 的代码、配置、调度、账本与报告目录；Muse 变更只限 `muse/`。
- 未经用户明确授权：不发正式邮件、不做自动外部投递、不购买付费服务、不公开敏感资料。
