# S2 盲测协议（真正新会话原文输入，不预告答案）

> 本协议为程序文件，不含答案。测试输入（新闻原文或链接）由用户在新聊天中直接提供，不写入本文件、不写入仓库；新会话在作出决策前不得以本协议以外的 S2 验收记录作为答案对照。
> 目的：验证 Muse 面对陌生新闻时能否自己抽取事实并判断事件关系，而不是验证预先写好的脚本候选。

## 一、隔离要求（必须满足，否则测试无效）

1. 用户在与旧会话隔离的新 Muse 聊天中开始测试；新会话不得使用旧聊天记忆作为判断依据。
2. 新会话首先独立读 GitHub 分支 `muse/pilot-2026-10-24` 上的 `MASTER_GOAL.md`、`DATA_SCHEMA.md`、`events/LEDGER-2026-10.md`、`events/WTD-2026-10-19-24.jsonl`，并以 WTD JSONL + LEDGER 中的不同 ID 合并为历史基线（废止记录不得再入池）。
3. **决策前禁读答案文件**：新会话在记录决策前不得打开 `reviews/S2-DEDUP-ACCEPTANCE-*.md`、`reviews/S2-DEDUP-RETEST-*.md`、`reviews/S2-DATE-BUGFIX-*.md` 及任何已含去重结论的复审记录；决策记录完成后再对照复核。
4. 用户提供的每篇测试输入只含新闻原文或链接，不得预告 event_id、新事实标志、update_of、关系判断或“这是重复/这是新事件”等结论；若输入为假设文本，必须明确标注“测试用假设，非真实新闻”，且只能进沙箱，不得进真实账本。

## 二、新会话必须输出的抽取字段（每篇输入一篇记录）

- 主体 subject、动作 action、对象 object、事实发生日 event_date、发表日 published_date、宣布日 announcement_date（如有，无则写“无”，不得用空值参与匹配）、来源 URL、证据短句。
- 与历史基线的关系：SAME_OCCURRENCE / SAME_STORY / NEW / BACKGROUND / UNRELATED，并写出匹配依据（主体、动作、对象、日期四项逐项比对）。
- 若判为已有事件：写出匹配的历史 ID；若判为新进展：写出 update_of 指向的历史 ID 及新事实点；若判为全新事件：写出新事件的事实与不重复理由。
- 测试前后的历史 ID 集合与数量（有效 ID、废止 ID 分开列），以及本轮是否产生新真实 ID。

## 三、通过 / 失败标准（任一失败即不得宣布 S2 通过）

- 通过（全部满足）：≥3 篇旧事件报道均未产生新真实 ID；旧事件的废止记录被正确识别并定向到当前有效 ID（不得复活废止 ID）；确有新事实的报道仅经 update_of 记录；背景/转载不被计为 P1；虚构或假设输入未写入真实账本；真实账本测试前后哈希一致。
- 失败（任一即失败，停止并记录）：产生重复新 ID；update_of 指向不存在、废止或主体不符的 ID；空值日期被算作匹配；同主体不同事件或同日不同动作被误并；背景被计为 P1；真实账本被改动；新会话在决策前读了答案文件。
- 失败时不得用“脚本曾通过”掩盖；须在记录中写明 exact input（脱敏后）、expected、actual，并修复后重测。

## 四、测试后记录要求

- 记录原始输入（链接或脱敏原文）、抽取字段、决策、匹配 ID、测试前后 ID 集合与数量、真实账本哈希前后、失败原因（如有）。
- 记录文件写入 `muse/reviews/`，经分支与 Draft PR 提交；PR 保持 Draft，定时任务继续暂停，不发邮件，不合并，不改动 QwenPaw。
- 本协议本身通过不等于 S2 通过；只有按本协议完成并通过的盲测记录，才能作为 S2 集成验收的证据。
