# SOURCE_REGISTRY — 核心信源清单（R2，WEEK-TO-DATE-PILOT）

> 窗口：2026-10-19 00:00 至 2026-10-24 14:01（北京时间，Asia/Shanghai），cutoff ISO 8601：`2026-10-24T14:01:11+08:00`。
> 借鉴 AIHOT 的信源健康思想，但不照搬它的 18 个 AI 示范源，也不照搬 T1=60 / T1_5=65 / T2=76 的 AI 领域分数线。本项目仍用八维 0–5 分与硬降级。
> 关键区分（AIHOT health.ts 的思想）：「来源自然低频」≠「因采集失败而静默」≠「已确认无信号」。Muse 本轮没有 RSS 直读器，巡检方式是网页搜索 + 原文打开，不是自动 RSS 采集，所以「未返回」只能写「本次搜索未返回」，不能写「该来源未发布」。
> 机器版：`SOURCE_REGISTRY.json`（与本表同源，字段一致）。

## 字段说明

`source_id, name, owner_entity, home_url, feed_or_section_url, tier, topic, expected_update_rhythm, last_checked_at, reachable, latest_seen_at, new_items, verified_items, unique_qualified_events, failure_reason`

- tier：L1 官方 / L2 垂类媒体 / L3 商业媒体 / L4 搜索与社交（仅线索，不直接支撑重大事实）。
- reachable：本轮是否通过搜索或打开触达该来源（是 / 否 / 仅搜索摘要）。
- new_items：本轮在该来源窗口内命中的条目数（搜索返回数，非全网总数）。
- verified_items：主代理或巡检员打开原文并锚定绝对日期的条目数。
- unique_qualified_events：该来源独家贡献的合格事件数（去重后）。
